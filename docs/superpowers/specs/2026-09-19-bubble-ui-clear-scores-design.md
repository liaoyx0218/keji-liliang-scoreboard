# 大屏气泡墙 + 平板学生端 + 长按清能量 设计

**日期：** 2026-09-19  
**项目：** keji-liliang-scoreboard  
**状态：** 已批准（对话确认 §1–§3）

## 1. 背景与范围

在现有单场积分赛基础上，**视觉与交互升级**：

| 页面 | 改动 |
|------|------|
| 教师大屏 `/t/:sessionId` | 列表改为 **能量泡泡墙**；新增 **长按 3 秒清空能量** 按钮 |
| 学生端 `/s/:sessionId` | **横屏平板** 布局与字号优化 |

**明确不改：**

- 创建页 `/`
- 「颁发科技小达人」颁奖 **弹层** 的视觉与逻辑（保持现状）
- 隐式初始化（角落三连击 → 清空本场、删组、`resetAt` 变化）
- API 除新增清分外，既有契约不变

**已确认的产品选择：**

- 泡泡墙：**错落能量泡**，分数影响大小/亮度（方案 1：CSS + 确定性布局）
- 典型组数：**7～12 组**
- 学生端：**横屏平板** 10～11 寸，四人围看
- 清能量：**仅 score → 0**，组保留，`resetAt` 不变

## 2. 教师大屏 · 能量泡泡墙（§1）

### 2.1 布局

- 保留标题「科技力量大 · 小组能量榜」、**颁发科技小达人** 按钮、隐式初始化热区。
- 主内容区为 **泡泡画布**（宽屏投屏友好，约 16:9 可用高度）。
- 每组一个 **圆形能量泡**：径向渐变 + 外发光（科技风 cyan，与 `theme.css` 一致）。

### 2.2 视觉映射

| 数据 | 表现 |
|------|------|
| 组名 | 泡内居中，字号随泡直径 `clamp` |
| 分数（能量） | 泡内数字；分数越高 **直径越大**（建议约 88px～168px）、**光晕越强** |
| 排名 | 不单独显示名次数字亦可；以大小/亮度体现领先 |

### 2.3 位置算法（方案 1）

- 输入：`LeaderboardEntry[]`（已按分降序、同分按 seq）。
- 输出：每组 `{ x, y, size }`（像素或 %），**同一场次稳定**（种子来自 `groupId` 或 `seq`，刷新不大跳）。
- **7～12 组**：中等密度；简单 **重叠检测/推开**，保证泡与泡、泡与画布边距可读。
- **1～6 组**：允许更大直径、更疏。
- **>12 组（偶发）**：直径下限再缩小，优先全部可见。

### 2.4 动效

- 新组：淡入 + 轻微 scale-up。
- 分数变化：短脉冲光晕或数字过渡（≤400ms），避免全屏闪烁。
- 可选极弱「呼吸」动画（1～2% scale/opacity）；实现时可默认开启但幅度要小，以免投屏晕眩。

### 2.5 空态

- 无组：仍显示「等待小组加入…」（可保留在画布上方或居中）。

### 2.6 实现要点

- React 渲染泡列表；CSS 变量 `--bubble-size`、`--bubble-glow`。
- 独立模块如 `layoutBubbles(entries, canvasSize)` 便于单测布局边界。
- 数据仍来自现有 `fetchLeaderboard` + WebSocket `leaderboard` 消息。

## 3. 教师大屏 · 长按 3 秒清空能量（§3 功能）

### 3.1 行为

- **仅将所有组 `score` 设为 0**。
- **不删除组**、不重置 `nextGroupSeq`、**不更新 `resetAt`**。
- 学生端 `localStorage` 绑定继续有效，**无需**「重新加入」。
- 执行后 WebSocket 广播完整排行榜；大屏泡变为最小档光晕/尺寸。

### 3.2 UI

- 显眼但克制的按钮，主文案：**「长按 3 秒清空能量」**；副文案可选：**「组保留，分数归零」**。
- 按下开始 **3 秒进度**（环形或条形）；**未满 3 秒松手则取消**；满 3 秒执行（不再二次 confirm，长按本身即防误触）。
- 成功：短提示「已全部清零」（行内或 toast 级）。

### 3.3 与隐式初始化对比

| | 长按清空能量 | 隐式初始化（三连击） |
|--|--------------|----------------------|
| 组 | 保留 | 删除 |
| 分数 | 0 | — |
| resetAt | 不变 | 更新 |
| 学生端 | 继续原组 | 需重新加入 |
| 课件二维码 | 不变 | 不变 |

## 4. 学生端 · 横屏平板（§2）

### 4.1 设备与方向

- **主场景：** 10～11 寸平板 **横屏**（如 1280×800、1920×1200）。
- 使用 `orientation: landscape` 与 `min-height` 做主布局；竖屏仅保证基本可用，不专项优化。

### 4.2 布局（play 态）

```
┌─────────────────────────────────────────────┐
│  轻量顶栏（可选「科技力量大」）                 │
├──────────────────┬──────────────────────────┤
│  左 ~38%          │  右 ~62%                  │
│  组名（超大）      │  「能量 +2」主按钮         │
│  能量：NN         │  占可用高度大部分          │
│  失败/加载文案     │                           │
└─────────────────────────────────────────────┘
```

- 主按钮 **「能量 +2」**：最小触控 **≥ 200×200px**，建议接近日标区域高度 ~70%；圆角大泡形，保留 `pulse` 与失败文案「没加上，再试一次」。
- **逻辑不变：** 非乐观更新、WS/`resetAt` 检测、needRejoin、join 流程均保持现有实现。

### 4.3 needRejoin / loading / error

- 全屏居中卡片，按钮与字号适配平板；文案不变。

## 5. 后端与 API（清能量）

### 5.1 SessionStore

```text
clearScores(sessionId: string):
  → { session } | { error: "NOT_FOUND" }
```

- 对该场所有 group：`score = 0`。
- 不修改 `resetAt`、`nextGroupSeq`、不删除 group。

### 5.2 HTTP

```text
POST /api/sessions/:sessionId/clear-scores
→ 200 { entries: LeaderboardEntry[] 或完整 LeaderboardPayload 形态与现有一致 }
→ 404 { error: "NOT_FOUND" }
```

- 成功后调用与 join/score 相同的 **onLeaderboard** + **onChange**（持久化）。

### 5.3 客户端

- 教师端：`clearScores(sessionId)` fetch 封装；长按完成后调用。

## 6. 错误与边界

| 情况 | 处理 |
|------|------|
| 清分时会场无组 | 仍 200，空榜广播 |
| 清分后学生 +2 | 正常从 0 累加 |
| 清分 vs 初始化 | 学生 binding 仅在初始化后失效 |
| 泡泡布局组数突变 | 重新 layout，动画过渡 size/position（position 尽量稳定） |

## 7. 验收清单

1. 大屏 7～12 组：气泡可读、重叠可接受，分数变化反映大小/光效。
2. 横屏平板：左组名+能量、右大按钮，四人围点可用。
3. 长按满 3s：全部分数 0，组名仍在，学生无需 rejoin，可继续 +2。
4. 隐式初始化仍删场；与清分按钮行为独立。
5. 颁奖弹层与创建页无回归。
