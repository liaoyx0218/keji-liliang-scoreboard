# 公开课小组积分赛系统设计

**日期：** 2026-09-17  
**项目：** keji-liliang-scoreboard  
**课程语境：** 人教版道德与法治三年级上册第 4 课《科技力量大》  
**状态：** 已批准（对话确认 §1–§6）

## 1. 目标与范围

单场公开课使用的**轻量 Web 积分赛工具**：教师投屏看实时排名，学生用手机扫码进入学生端，以「设备」为单位组队加分。

### 成功标准

- 课前把**唯一**学生端二维码放进课件即可开课；大屏只显示排名。
- 每多一台学生设备扫码，自动成为新组（组一、组二…）；约四人共用一台设备。
- 学生端一键 +2，可重复；大屏实时更新。
- 同设备刷新后回到原组；教师可隐式初始化整场（链接与二维码不变）。

### 非目标（首版不做）

- 账号登录、多场历史、学期累计
- 预建小组、改组名、跨设备进同一组
- 暂停加分、单组删改分、自定义分值、加分限速
- 二维码展示在大屏上

## 2. 用户与场景

| 角色 | 场景 |
|------|------|
| 教师 | 课前创建场次、复制链接/下载二维码贴进课件；课中投屏看「科技力量大 · 小组能量榜」；必要时隐式初始化重来 |
| 学生（三年级） | 扫课件二维码 → 见本组名与能量分 → 点大按钮「能量 +2」 |

## 3. 架构

采用**方案 1：轻量 Web + 自建实时通道**。

```
课件二维码 ──► 学生端 Web (/s/:sessionId)
                      │
                      ▼
              后端 API + WebSocket
                      │
教师浏览器 ──► 大屏 Web (/t/:sessionId) 订阅排行榜
开赛前   ──► 创建页：复制链接 / 下载二维码（非投屏主界面）
```

- **一设备一组**：首次加入分配递增组号；`localStorage` 绑定 `sessionId + groupId`（及用于判定重置的时间戳）。
- **加分**：仅允许给本设备已绑定的组 +2；服务端原子自增后向场次房间广播排行榜。
- **初始化**：清空该场全部组与分数，`nextGroupSeq` 归 1，更新 `resetAt`；学生端发现失效后提示重新加入。课件二维码（同一 `sessionId`）保持有效。
- **无账号**：场次 ID 为足够长的随机串；大屏用场次 URL 进入；初始化入口低对比隐藏，降低误触。

技术形态：Web 前端 + 小后端 + WebSocket；具体框架在实现计划中选定。数据建议**轻量持久化**（如 SQLite/文件），避免课中进程重启丢场。

## 4. 页面与交互

### 4.1 创建 / 取码页（教师，非大屏）

- 创建场次后展示：学生端链接、二维码图片、一键复制/下载。
- 提供「打开大屏」入口。
- 此页用于备课，不作为投屏主界面。

### 4.2 教师大屏 `/t/:sessionId`

- 满屏实时排名（组名 + 分数）；按分数降序，同分按组号升序。
- **不展示二维码**。
- 轻量标题，例如：「科技力量大 · 小组能量榜」。
- 隐式初始化：角落低对比热区（如连点版本号 3 次或长按）→ 二次确认「清空本场？」→ 清空并广播空榜。

### 4.3 学生端 `/s/:sessionId`

1. 若本地有绑定且服务端组仍有效（未被更新的 `resetAt` 淘汰）→ 进入原组操作页。
2. 否则请求加入 → 分配「组N」→ 写入 `localStorage` → 操作页。
3. 操作页：组名、当前能量分、超大「能量 +2」按钮（每次请求 +2）。
4. 场次已重置：提示「本场已重新开始，点一下重新加入」→ 清本地 → 重新加入。

## 5. 数据模型

### Session

| 字段 | 含义 |
|------|------|
| `id` | 场次 ID（URL / 二维码唯一码） |
| `status` | 首版可固定为可加分（`active`） |
| `createdAt` / `resetAt` | 创建与最近初始化时间 |
| `nextGroupSeq` | 下一组序号，初始化后回到 1 |

### Group

| 字段 | 含义 |
|------|------|
| `id` | 稳定 ID（设备绑定用） |
| `sessionId` | 所属场次 |
| `seq` | 组序号 → 显示名「组一」「组二」… |
| `score` | 非负整数，步进 +2 |
| `createdAt` | 加入时间 |

### 客户端绑定（localStorage）

```text
{ sessionId, groupId, resetAt }
```

恢复规则：加入成功时把当时的 `session.resetAt` 写入本地。之后打开学生端时，仅当服务端仍存在该 `groupId` **且** `session.resetAt === localStorage.resetAt` 时恢复原组；否则清本地并走重新加入。

## 6. API 与实时（逻辑契约）

首版可用 HTTP 写操作 + WebSocket 推送（或等价 SSE）。

| 动作 | 行为 |
|------|------|
| 创建场次 | 生成 `sessionId`，返回大屏 URL、学生 URL |
| 加入 | 创建 Group，`seq = nextGroupSeq++`，返回组信息与当前 `resetAt` |
| +2 | 校验绑定组属于本场 → `score += 2` → 广播排行榜 |
| 排行榜快照 | 大屏进页拉取全量 |
| 初始化 | 删组、`nextGroupSeq = 1`、更新 `resetAt`、广播空榜 |
| WebSocket 房间 | 按 `sessionId`；消息以完整排行榜为主（组数通常不多） |

并发：服务端对 `score` 做原子自增，避免连点丢分。  
失败策略：**不做乐观更新**；+2 失败时提示「没加上，再试一次」。

## 7. 异常与边界

| 情况 | 处理 |
|------|------|
| 初始化后旧设备回来 | 提示重置并重新加入 |
| 断网 | 失败提示，本地分数不瞎涨 |
| 大屏刷新 | 同链接拉快照 + 重新订阅 |
| 同设备重复扫码 | 恢复原组，不新建 |
| 换机想进同组 | 不支持；误多组则整场初始化 |
| 连点刷分 | 允许（课堂信任制） |
| 链接泄露 | 长随机 `sessionId`；初始化入口隐藏 |

## 8. 视觉与文案

- **对象：** 三年级；字大、对比强、按钮巨大、文案短。
- **风格：** 科技风——深色底 + 青/电蓝光效、细网格或轻粒子；明亮可亲，非暗黑赛博、非复杂控制台。
- **课程贴合：** 分数口语化为「能量」；按钮「能量 +2」；大屏标题点明《科技力量大》。
- **学生反馈：** 点按短光效（及可选震动）；错误用人话。
- **避免：** 紫白渐变套模板、奶油衬线公文风、英文术语（Session/Leaderboard）、首版角色养成/商店/剧情。

## 9. 验收清单

1. 大屏无二维码，可见空榜或等待态。
2. 创建页得到唯一学生链接/码；设备 A→组一，设备 B→组二。
3. 组一点 +2 → 本地与大屏均为 2 且排序正确；连点累加。
4. 设备 A 刷新后仍为组一，分数保留。
5. 隐式初始化后大屏清空；旧端提示重置；再加入从组一计；课件码仍可用。
6. 断网点 +2 有失败提示且分数不误增。

手测：2～3 部手机 + 一台上大屏电脑走完以上步骤。
